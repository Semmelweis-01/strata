# strata

**把一个文件的 git 历史，读成一柱地质岩芯。**

零依赖 · 确定性 · 一条命令

<img src="assets/core.svg" width="720" alt="从 git 历史渲染出的岩芯">

</div>

[English](README.md)

每个文件都是一口钻孔。每次提交都是一层沉积。

```
$ strata engine.js
```

层的厚度是改动量。删的比加的多，层里就留下化石。
比中位数重四倍的提交会剪断岩柱：这是断层，其下整体错位。
合并提交从侧面横切地层：这是岩脉。

## 安装

```
npx strata <file>
```

需要 Node 18+ 和 PATH 里的 `git`。没有别的。

## 用法

```
strata <file>              渲染岩芯
strata --svg out.svg <f>   输出独立 SVG
strata --json <f>          输出 Core 的 JSON
```

| 参数 | 含义 |
|---|---|
| `--width <n>` | 岩芯宽度（格），默认 24 |
| `--max-rows <n>` | 最大行数，默认 40 |
| `--ascii` | 仅用 ASCII 字符，适配无 Unicode 的终端 |
| `--color <m>` | `truecolor` / `256` / `none` |
| `--theme <t>` | `dark` / `light`（仅 SVG） |
| `--no-labels` | 隐藏深度与提交标题栏 |

## 映射关系

| 熵 | 变成 |
|---|---|
| 提交改动量（增删行数） | 层的厚度 |
| 删除多于新增 | 层中的化石 |
| 改动量 ≥ 中位数 4 倍 | 断层，其下岩柱错位 |
| 合并提交 | 横切地层的岩脉 |
| 提交之间的时间 | 以 Ma 表示的深度 |
| 文件的身份 | 登记号，不随路径写法改变 |

## 确定性

同一文件、同一段历史，输出逐字节相同。没有 `Math.random`，没有 `Date.now`。
渲染是一个纯函数：

```
git 历史 -> Core -> 终端字符串 / SVG
```

这就是全部设计。它可以被测试，而且它被测试了：64 个测试，零依赖。

## 为什么做这个

`git blame` 告诉你该怪谁，但它不告诉你这个文件经历过什么。

它不解决任何问题。它只是把记录读出来。
